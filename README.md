# 諮詢紀錄結構化：用 Claude API 把口語摘要轉成固定欄位

> Turn free-text sales consultation notes into structured records with the Claude API: schema-enforced tool use, program-side validation, business-rule guardrails, and a retry loop with error feedback. Iterated over three real API runs. Python standard library only.

顧問每天寫的諮詢摘要是口語文字，例如「已報 6 個月方案，說下週三前回覆」。要追蹤名單時，得一筆一筆讀，再手動整理出目標、狀態、下次跟進日期。
這支程式用 Python 呼叫 Claude API，把摘要轉成固定欄位的表格，並由程式驗證結果，**不直接相信模型的輸出**。

只用 Python 標準函式庫（3.9 以上），不需安裝任何套件。範例資料全部虛構。

## 要解決的問題

1. **摘要格式不一**：每位顧問寫法不同，難以篩選「本週該跟進誰」
2. **用詞容易誤判**：例如「已報」在我們的用法是**已報價**，不是成交
3. **AI 會補資訊、會算錯日期**：摘要沒寫預算，模型可能自己猜；「下週三」也可能算成本週三

## 設計

| 設計 | 作法 |
| --- | --- |
| **強制輸出格式** | 用 tool use 搭配 JSON Schema，讓模型只能照固定欄位回傳 |
| **選項限定** | 身分、目標、狀態、上課方式都用 enum，模型不能自創類別 |
| **不准猜** | 摘要沒寫的欄位一律填 null |
| **日期由程式算** | 程式先產生「日期＋星期＋本週／下週＋月底」對照表給模型查，不讓模型自己推算 |
| **程式端驗證** | 檢查欄位、選項、日期格式；摘要寫「下週」，跟進日期就不能落在當週 |
| **業務規則把關** | 沒寫成交或繳費不能判已成交；有「已報」就是已報價（優先於考慮中）；狀態依據必須是摘要原文 |
| **錯誤回饋重試** | 驗證沒過時，把錯誤訊息告訴模型重試一次 |
| **分清楚誰說的** | 「必須處理」由程式依業務規則判斷（例如考慮中卻沒有跟進日期）；模型認為模糊的欄位只放在「參考」 |

## 實際執行：三輪改進

用 8 筆虛構摘要、實際呼叫 Claude API（`claude-haiku-5-5`）跑了三輪。每一輪都把發現的問題改成規則，再重跑。

| 版本 | 狀態正確 | 跟進日期正確 | 發現的問題 | 下一版的修正 |
| --- | --- | --- | --- | --- |
| v1 | 7/8 | 3/4 | 「下週三」算成本週三；「月底前會回覆」判成未提及；8 筆全部被標需確認，等於沒標；自行把「姓蔡」加上「同學」 | 程式產生日期對照表；需確認改由程式依業務規則判斷；稱呼只能照原文 |
| v2 | 7/8 | 3/4 | 摘要同時有「已報」和「會回覆」時，判成考慮中；「月底」沒算出日期 | 狀態優先順序（已報價 > 考慮中），並由程式檢查；對照表標出月底 |
| v3 | **8/8** | **4/4** | 模型標「模糊」的標準不一致；仍會自行推測稱呼（把林媽媽的女兒稱為「林同學」） | 輸出拆成「必須處理」與「參考」兩欄（純程式調整，不需重跑） |

稱呼推測不影響追蹤，列為已知限制。v3 的「必須處理」只剩 2 筆，兩筆都是業務真的該處理的：陳先生還在考慮、但沒約下次聯絡時間；蔡只留電話，狀態不明。

三輪的原始輸出保留在 `examples/real_run_v1.json`～`real_run_v3.json`（當時的欄位格式，未拆欄）。v1 的用量為輸入 14,813、輸出 3,115 token。

另外，第一次呼叫就遇到 API 錯誤：schema 的欄位名稱只能用英文、數字、底線。所以程式內部改用英文鍵（例如 `next_follow_up`），輸出時再轉回中文標題。

## 執行方式

**免費示範（不呼叫 API）**：用預先寫好的模型回覆跑完整流程，包含驗證與重試。

```bash
python notes_to_json.py --input examples/sample_notes.txt --mock examples/mock_responses.json --out output/leads.csv
```

**實際呼叫 Claude API**：到 Anthropic Console 建立 API key 後執行。預設使用最便宜的型號，可用 `--model` 更換。

```powershell
# Windows PowerShell
$env:ANTHROPIC_API_KEY="你的金鑰"
python notes_to_json.py --input examples/sample_notes.txt --out output/leads.csv
```

```bash
# macOS / Linux
export ANTHROPIC_API_KEY=你的金鑰
python3 notes_to_json.py --input examples/sample_notes.txt --out output/leads.csv
```

輸出 `leads.csv`（Excel 可直接開啟，中文不亂碼）和 `leads.json`，並列出 token 用量。

**API key 不可以放進程式或上傳到 GitHub**：只用環境變數讀取，`.gitignore` 也排除了 `.env` 與輸出資料夾。

## 學到的事

- **AI 第一次不會完美，重點是設計能抓到錯誤的機制**：每一輪的錯誤都變成一條程式檢查，下一輪就不會再漏掉
- **語言模型不擅長日期計算**：與其要求它算對，不如由程式算好對照表讓它查
- **公司內部用語要寫成規則，並由程式再檢查一次**：例如「已報」是已報價；同時出現多種狀態時，要定出優先順序
- **分清楚哪些判斷交給模型、哪些交給程式**：模型負責理解口語，業務上「一定要處理」的判斷由程式決定，結果才穩定
- 要拿到穩定的結構化輸出，tool use 加 JSON Schema 比在提示詞裡要求「輸出 JSON」可靠
